# 之后怎么把这个项目讲明白

你先能操作演示，再按下面顺序理解。无需一上来学习复杂 Agent 框架。

## 1. 一个问题怎样变成回答

以“深水埗有什么小吃”为例：

1. 浏览器把这句话送到 `app.py` 的 `/api/ask`。
2. 应用通过 MCP 客户端启动本地工具进程。
3. 客户端先握手、询问有哪些工具，再调用 `search_places`。
4. 工具从资料库找出相关条目，返回介绍和来源。
5. 没有模型密钥时，程序整理成固定格式的资料摘录。
6. 有密钥且主动开启后，模型只拿这些片段来组织回答。
7. 页面展示回答、引用卡和工具调用记录。

这类似于去图书馆咨询：问题是你的需求，检索模块是查目录的人，资料库是书架，大模型是根据查到的资料写介绍的人。这个类比只能帮助理解分工；程序没有人的理解和查证能力，找到资料或带了引用也不保证每句话正确。

## 2. RAG 是什么

RAG 是“检索增强生成”：**先查资料，再让大模型依据资料回答。** 本项目先把官方网页内容人工概述为小条目，用中文二字片段与名称匹配检索。BM25 是一种关键词相关度评分方法：在某条资料里出现得较多、但不是所有资料都常见的词，通常更能帮助定位。

当前没有模型 Key 的模式只完成“检索 + 资料摘录”，不能声称已调用大模型完成生成。真实模型接入代码已经提供，仍需之后用真实服务验证。

## 3. MCP 是什么

MCP 是“模型上下文协议”，这里可以理解为应用调用工具时遵守的一套通信规则。

类比：USB 规定连接和传数据的方式，MCP 规定如何发现工具、传入参数、拿回结果。本地检索工具和高德搜索工具可以使用同一种协议，但能力不同。类比的限制是 MCP 是软件通信协议，不是实体接口，也不保证接上的工具一定正确。

本地工具通过 stdio 通信，也就是两个进程之间用标准输入／输出传递协议消息。高德适配器通过 Streamable HTTP 通信，也就是走网络请求。没有 Key 时，本地工具真实可用，高德不会被调用。

## 4. 行程是怎么排的

先过滤地区、室内和公共空间条件；再把地点按街区分组；按兴趣评分选择地点；把相近地点放在一起；最后加上停留时间和转场余量。

这类似安排实验课：先看哪些实验符合课程要求，再把同一个实验室的任务安排在一起，避免在校区之间反复跑。但这里使用的是简单规则，没有证明路线最短，也没有核实当天营业。交通分钟数只是预留时间。

## 5. 面试时先能回答这五个问题

- 你的资料从哪里来，怎么知道它不是实时信息？
- 为什么要先检索，而不是直接让大模型自由回答？
- 哪一段代码实际使用了 MCP？怎样从记录里看到？
- 没有找到资料、模型报错、用户条件冲突时，系统分别怎么办？
- 哪些部分是你自己理解并修改的，哪些是 Codex 辅助完成的？

建议你做的第一处改动：找一个你熟悉且有官方资料的地点，补入 `places.json`，检查搜索、行程、来源卡是否同步变化。这个改动比背一串框架名字更容易展示理解。

最简单地说：这个项目是“查香港资料、调用工具、排旅行草案”的小系统；下一步是理解数据怎样在这些模块之间流动。
