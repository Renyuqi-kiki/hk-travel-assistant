# Development conventions
- Keep the Python backend and native web interface simple and readable.
- Never commit real .env files, credentials, virtual environments or caches.
- Distinguish local evidence, mocked contracts and real external-service verification.
- Do not tune against frozen retained questions or report development examples as independent accuracy.
- Run the relevant tests and local stdio protocol checks after behavior changes.
- Keep citations traceable. Coordinates, travel times and schedule labels are planning assumptions.
- No deployment, account/payment actions or external messages without an explicit task request.
